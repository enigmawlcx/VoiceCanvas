# GitHub 私有仓库发布前审计设计

## 目标

在不连接 GitHub、不创建远端仓库、不提交和不上传的前提下，完成 VoiceMax 项目的本地发布前审计，修正文档，并生成必要的 Git 相关文件，最终提供一份供用户确认的上传准备报告。

## 范围

- 检查仓库内全部人工维护文档，包括根目录说明、`docs/` 下的规格与计划，以及脚本中的使用说明。
- 核对文档与当前源码、依赖、启动方式、构建方式及测试方式是否一致。
- 扫描工作区和 Git 已跟踪文件中的密钥、令牌、个人绝对路径、本地数据库、缓存、虚拟环境、构建产物和其他不应上传的内容。
- 完善 `.gitignore`，并仅在确有跨平台文本或二进制属性需求时新增 `.gitattributes`。
- 检查 Git 分支、历史、已跟踪文件与未跟踪文件状态，但不改写历史。
- 运行与改动风险相称的文档、忽略规则和项目测试验证。

## 明确排除

- 不连接或登录 GitHub。
- 不创建 GitHub 远端仓库或配置 `origin`。
- 不执行 `git add`、`git commit`、`git push` 或历史改写。
- 私有仓库阶段不新增开源许可证。
- 不清理或删除用户现有的本地构建产物、缓存、虚拟环境或工作树；只通过忽略规则阻止其进入上传范围。

## 实施方法

先建立仓库文件清单，并区分已跟踪、未跟踪和已忽略内容。随后逐份读取文档，同时以源码、依赖文件、测试和构建脚本作为事实依据进行交叉核对。发现问题后，只修改与发布准备直接相关的文档和 Git 配置文件，不开展无关重构。

敏感信息审计覆盖常见凭据格式、配置字段、环境变量赋值、私钥头、个人绝对路径和本地数据文件。任何疑似真实凭据都按高风险处理，并明确报告其当前是否已进入 Git 历史；不会在未经用户授权时改写历史。

## 产物

- 经核对和必要修正的项目文档。
- 完善后的 `.gitignore`。
- 经审计确认有必要时创建的 `.gitattributes`。
- 发布前审计报告，列出已完成项、风险、建议上传内容、必须排除内容和需要用户决定的事项。

## 验收标准

- Git 预览清单中不包含虚拟环境、Python 缓存、测试缓存、构建目录、发行包、本地数据库、日志、系统元数据或临时工作树。
- 人工维护文档中的运行、测试、构建和配置说明与当前项目文件一致。
- 对工作区和 Git 已跟踪内容完成敏感信息扫描，所有命中均经过人工语境复核并记录结论。
- 项目测试以当前环境可执行的完整测试命令通过；若环境导致无法执行，报告准确的阻塞原因和已完成的替代验证。
- 最终停在本地未提交状态，等待用户确认下一阶段的 GitHub 配置与首次上传。
