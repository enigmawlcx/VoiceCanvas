# 工作台（Studio）重构设计文档

- 日期：2026-07-08
- 状态：已实现（2026-07-10）
- 实现计划：docs/superpowers/plans/2026-07-08-studio-redesign.md（已完成）
- 关联文档：`docs/superpowers/specs/2026-07-08-voice-max-design.md`（原始整体设计）

## 1. 背景与目标

现有工作台是"原文文本框 → 点击 AI 润色标注 → 标注编辑器文本框 → 解析分段 → 合成"的两栏流程。本次重构目标：

1. 合并为单一大文本框，所有编辑操作（含润色结果）都在同一个文本框内完成。
2. "润色"改为**只添加情绪/语气词标注，不改动原文文字**，并以大按钮形式暴露全部受支持的情绪与语气词，供手动插入。
3. 草稿改为自动保存（10 秒一次）+ 页面切换/应用重启不丢内容，同时保留手动"保存草稿"与"解析分段"。
4. 新增"清空工作台"按钮，一键恢复到初始空状态。
5. 合成设置里音色下拉框重新排序。
6. 语音合成启用双声道输出。

### 非目标（YAGNI）
- 不做草稿历史版本列表/多草稿管理 UI（当前也没有，本次不新增）。
- 不做情绪标签在一行内多次切换的解析能力（emotion 仍是"整段一个值"的现有模型）。
- 不做双声道/单声道的用户可配置项，直接固定为双声道。

## 2. 交互与流程设计

### 2.1 页面结构（对应布局方案 B）

```
┌─────────────────────────────────────────────────────────┐
│ 工作台                                                    │
├───────────────────────────────┬─────────────────────────┤
│ [润色] [解析分段] [保存草稿]     │  情绪                     │
│ [清空工作台]                    │  [开心][悲伤][生气]...    │
│                                │  （9 个大按钮）            │
│  ┌───────────────────────────┐│  ──────────────           │
│  │                           ││  语气词                    │
│  │      大文本框              ││  [笑声][轻笑][咳嗽]...     │
│  │  （原文 → 润色结果 →       ││  （19 个大按钮，可滚动）    │
│  │   人工继续编辑）            ││                           │
│  │                           ││                           │
│  └───────────────────────────┘│                           │
├───────────────────────────────┴─────────────────────────┤
│ 合成设置（音色 / 语速 / 音量 / pitch / 音效器）              │
├───────────────────────────────────────────────────────────┤
│ 分段列表 + 整篇合成并导出                                    │
└─────────────────────────────────────────────────────────┘
```

右侧按钮面板固定宽度、独立滚动，编辑文本时始终可见。

### 2.2 状态与生命周期

单文本框内容即"工作台正文"，其状态机：

1. **初始/清空状态**：文本框为空，无草稿记录，所有合成设置为默认值。
2. **编辑中**：用户输入或粘贴纯文本；每次内容变化标记为 dirty，启动/重置 10 秒自动保存定时器。
3. **已标注**：点击"润色"后，文本框内容被替换为带 `[emotion]` / `(语气词)` 标注的文本；仍可继续手动编辑（含用按钮插入更多标签）。
4. **草稿持久化**：自动保存或手动"保存草稿"都写入同一条 `projects` 记录（首次写入时创建）。
5. **清空**：删除该记录、清空文本框与所有设置，回到状态 1。

页面切换（离开工作台再回来）不销毁这条状态——文本框内容在切换期间保留在 `localStorage`，回到工作台时优先用内存/`localStorage` 中的最新内容渲染，避免与自动保存的时间差造成的短暂回退。

## 4. 润色标注：只加标注、不改原文

### 4.1 Prompt 与输出格式

`polish.py` 的 system prompt 改为要求模型只返回 JSON（不要 markdown 代码块、不要解释）：

```json
{"segments": [{"text": "……", "emotion": "happy"}, {"text": "……", "emotion": ""}]}
```

约束：
- `text` 必须是原文的逐字节选（可跨句、可整段），只允许在其中**插入**语气词标签（如 `(laughs)`），不允许增删改原文任何文字、标点替换或复述。
- `emotion` 为空字符串表示不标注情绪。
- 所有 `segments[].text` 依次拼接后，去除空白与语气词标签，必须与原文（同样去除空白后）完全一致。

### 4.2 校验与重试算法

```
attempt 1: 调用 LLM → 解析 JSON → 校验拼接结果 == 原文（忽略空白，剔除已识别的语气词标签）
  通过 → 成功，用 segments 生成标注文本
  失败（JSON 解析失败 或 内容不一致）→
attempt 2: 追加一条纠错 user message："上次结果修改了原文文字，请重新处理，
           必须逐字保留原文所有文字与标点，只能分段、标注情绪、插入语气词标签"
  → 重新调用 LLM → 同样校验
  通过 → 成功
  失败 →
fallback: 规则兜底（不调用 LLM）——按空行拆段，段内再按句末标点（。！？…；换行）
          拆分，emotion 全部为空，不插入任何语气词标签。
          响应中附带 notice 字段，前端提示用户"AI 未能在保留原文前提下完成标注，
          已自动按标点分段，可手动点击情绪/语气词按钮补充"。
```

### 4.3 生成标注文本

无论走哪条路径，最终都用 `segments` 生成与现有格式兼容的标注文本字符串：

```
[emotion] text        # 有 emotion 时
text                  # emotion 为空时
```

这行文本直接写回文本框，并复用现有 `parse_annotated_text` 做后续分段/合成——**不改动**这部分现有逻辑。

### 4.4 接口变化

`POST /api/studio/polish` 响应新增可选字段：

```json
{ "annotated_text": "...", "segments": [...], "notice": "已按标点自动分段，未加情绪/语气词" }
```

`notice` 仅在触发兜底时出现，前端据此显示提示（沿用现有 `#polish-result` 提示位置，用 warning 样式）。

### 4.5 重复点击"润色"

允许重复点击，每次都以**当前文本框内容**作为原文重新生成并整体替换文本框内容（等同"重新标注"，会覆盖之前手动做的标签编辑）。不做"仅追加"的增量逻辑，保持实现简单、行为可预期。

## 5. 情绪/语气词按钮插入行为

- **情绪按钮**：点击后，定位光标所在**行**，检查行首是否已有合法 `[emotion]` 标签——有则替换，没有则在行首插入 `[emotion] `。插入后光标保持在原来的相对位置（整体后移相应字符数）。
- **语气词按钮**：直接在光标当前位置插入 `(tag)`；若插入点左右是非空白字符，自动补一个空格，避免和文字粘连。
- 两类按钮均从 `/api/studio/tags` 拉取列表渲染，中文 label 显示在按钮上，`data-id` 存实际标签值。

## 6. 自动保存与草稿

### 6.1 数据模型

不改 `projects` 表结构。约定：工作台的"当前草稿"就是 `projects` 表中的某一行，`source_text` 与 `annotated_text` 两列写入相同的文本框内容（工作台已不区分原文/标注两份文本）。

### 6.2 保存时机

- 文本框内容变化后启动/重置一个 10 秒防抖定时器，到时若内容仍是 dirty 状态则触发保存。
- "保存草稿"按钮：立即触发一次保存（绕开防抖等待），与自动保存复用同一保存函数。
- 保存函数逻辑：若本地无草稿 id → `POST /api/studio/projects` 创建，记录返回 id；若已有 id → `PUT /api/studio/projects/{id}` 更新。

### 6.3 草稿 id 存储与恢复

- 草稿 id 存浏览器 `localStorage`（key 如 `voicemax.studio.draftId`）。
- 工作台页面加载时：
  1. 若模块内存中已有未提交的最新文本（同一次应用运行内切换过页面）→ 直接用内存值渲染，无需请求后端，保证"切页不丢"是瞬时的。
  2. 否则读取 `localStorage` 的草稿 id → `GET /api/studio/projects/{id}` 拉取内容渲染（覆盖应用重启场景）；id 不存在或请求 404 则视为空草稿，按初始状态渲染并清掉失效的 `localStorage` id。

### 6.4 清空工作台

点击"清空工作台"：
1. 清空文本框内容。
2. 合成设置区所有滑块/下拉恢复默认值（语速 1.0、音量 1.0、pitch 0、音效器三个滑块 0、音色下拉恢复未选中默认提示项）。
3. 分段列表恢复初始提示文案。
4. 若存在草稿 id：`DELETE /api/studio/projects/{id}`，并清除 `localStorage` 与内存中的草稿 id/内容。
5. 效果等同首次进入工作台页面。

## 7. 合成设置调整

### 7.1 音色下拉排序

`web/js/pages/studio.js` 的 `buildVoiceOptionsHtml` 分组顺序调整为：

```
我的克隆音色 → 我的设计音色 → 系统音色
```

（原顺序：系统音色 → 我的克隆音色 → 我的设计音色）

### 7.2 双声道输出

`app/services/synthesize.py` `_build_t2a_payload` 中：

```python
"audio_setting": {
    ...
    "channel": 2,   # 原为 1；MiniMax API：1=单声道，2=双声道
},
```

`pydub`/`AudioSegment` 对拼接双声道音频无额外改动需求（自动按源文件声道处理）。

## 11. 风险与取舍

- **重试增加延迟**：最坏情况下"润色"要调用 2 次 LLM，响应时间翻倍。接受此代价以换取"绝不改原文"的强保证。
- **兜底质量较低**：规则兜底不加情绪/语气词，标注质量下降，但**保真度优先于自动化程度**，且用户可用按钮手动补充。
- **`localStorage` 依赖 webview 持久化**：pywebview 默认使用持久化的 WebKit 数据目录，`localStorage` 预期跨应用重启保留；若用户环境清除了 webview 数据目录，会退化为"仅剩后端已保存的最后一次自动/手动保存内容"（草稿 id 丢失，但可通过接受该 id 已知的极端场景不做进一步兜底，符合 YAGNI）。
