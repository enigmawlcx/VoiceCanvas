# VoiceCanvas 面向用户的双语 README 设计

## 背景

当前 `README.md` 已能概括项目功能、源码安装、测试和打包方式，但整体更像开发摘要，缺少首次配置和基本使用流程。文档还遗漏了最新的音频行为；macOS 应用包名称需与当前构建产物保持一致。

本次更新面向最终用户重组中文 README，同时新增内容和结构完全对应的英文 README。文档只描述已由当前代码、测试或构建脚本证实的行为，不添加未经验证的发行渠道、平台兼容性或功能承诺。

## 目标

- 让首次接触项目的 macOS 用户能够理解产品用途、完成源码安装并启动应用。
- 说明首次配置和从文本到音频导出的基本工作流。
- 准确记录当前音频格式、MP3 比特率、段间静音和生成期间配置锁定行为。
- 明确本地数据、Keychain 凭据和默认输出目录的存储方式。
- 保留测试、打包和项目结构信息，但将其放在用户使用说明之后。
- 提供与中文文档章节、事实、命令和限制完全对应的英文版本。

## 非目标

- 不修改应用代码、配置、依赖或构建脚本。
- 不添加截图、徽章、下载地址或发布流程。
- 不承诺 Windows、Linux 或未经验证的旧版 macOS 支持。
- 不把历史设计计划当成当前产品行为写入 README。
- 不把 README 扩展为完整 API 参考或开发者贡献指南。

## 文件与语言

- `README.md`：简体中文主文档。
- `README_EN.md`：英文文档。
- 两份文档采用相同的章节顺序、命令示例和事实范围。
- 中文首次出现产品名时写作“声绘魔法（VoiceCanvas）”；英文固定写作 `VoiceCanvas`。

## 信息架构

两份 README 均按以下顺序组织：

1. 产品简介
2. 核心功能
3. 系统要求
4. 安装与启动
5. 首次配置
6. 基本使用流程
7. 音频输出说明
8. 数据与隐私
9. 测试
10. macOS 打包
11. 项目结构
12. 参与贡献与安全
13. 开源许可证

其中产品简介是第 1 个逻辑项但不使用二级标题，因此两份 README 各有 12 个二级标题。文档优先回答“这是什么、如何开始、如何使用”，再提供测试、打包、代码目录、参与贡献与许可证等开发和发布信息。

## 内容要求

### 产品与功能

- 产品定位为个人使用的 macOS 桌面应用，通过 MiniMax API 提供语音合成、音色克隆、音色设计和用量报表。
- 配置模块包括 API Key、Group ID、API Base URL、默认模型、音频格式、采样率、MP3 比特率、保存目录和连接测试。
- 工作台流程包括原文输入、AI 润色标注、标注编辑、分段试听、失败段重试、整篇合成和导出。
- 标注语法说明为 `[emotion]` 情绪标签和 `(语气词)`。
- 音色库包括远端音色浏览、音色克隆、文本音色设计和本地备注管理。
- 报表包括按天/周趋势、按功能汇总、明细筛选与分页、CSV 导出和费用估算。

### 安装与使用

- 系统要求只声明当前已知条件：macOS、Python 3.13 或更高版本、有效的 MiniMax API 凭据。
- 使用现有 `.venv` 创建、激活和 `requirements.txt` 安装命令。
- 启动命令使用 `python3 -m app.main`。
- 首次配置说明用户保存 API Key，按账户情况填写 Group ID 或切换 API Base URL，然后测试连接并设置输出参数。
- 基本流程按“配置 → 输入 → 润色/编辑 → 试听 → 合成/重试 → 导出”描述。

### 音频行为

- 支持 MP3、WAV 和 FLAC。
- MP3 支持 32、64、128、256 kbps，合成段和最终拼接输出均使用 CBR。
- WAV 和 FLAC 不使用 MP3 比特率设置。
- 每两个成功合成的相邻音频段之间插入固定 1 秒静音；首尾不额外插入静音。
- 一次生成开始时锁定音频格式、采样率和比特率，分段、重试和最终拼接复用同一份配置。
- `imageio-ffmpeg` 提供音频拼接所需的 ffmpeg 二进制，不要求用户另行安装系统 ffmpeg。

### 数据与隐私

- 配置和 SQLite 数据默认存放在 `~/Library/Application Support/VoiceCanvas/`。
- API Key 存入 macOS Keychain，不以明文写入配置文件。
- 默认音频输出目录为 `~/Music/VoiceCanvas`。
- 从旧版 `VoiceMax` 升级时，应用会尝试迁移旧数据目录和 Keychain 凭据；迁移失败时保留安全回退行为。
- 明确 MiniMax API 请求会发送到用户配置的服务地址，不能把“数据全部本地存储”误写成“所有处理均离线”。

### 测试与打包

- 测试命令为 `pytest -v`，并说明测试使用 `respx` 拦截 MiniMax 请求，不消耗真实额度。
- 架构打包命令保留 `scripts/build_app.sh arm64` 和 `scripts/build_app.sh x86_64`。
- 构建脚本会安装或更新构建依赖、运行完整测试并生成对应架构的应用。
- 应用包路径写作 `dist/<arch>/声绘魔法.app`；`VoiceCanvas` 仅是构建配置中的内部 EXE/COLLECT 名称。
- x86_64 构建需要 Rosetta 2；`universal2` 只在 Python 解释器和全部依赖均支持时可用。

### 参与贡献、安全与许可证

- 中英文文档均要求贡献前阅读 [CONTRIBUTING.md](../../../CONTRIBUTING.md)。
- 中英文文档均要求未修复漏洞按 [SECURITY.md](../../../SECURITY.md) 私密报告，不要公开披露敏感信息。
- 中英文文档均链接英文原版 [MIT License](../../../LICENSE) 和 [中文说明](../../../LICENSE.zh-CN.md)，并明确中文说明仅辅助理解，法律效力以英文原文为准。

## 准确性边界

- README 中的功能描述以当前 `main` 源码、自动化测试和构建脚本为依据。
- 不声称已经人工验证需要真实 MiniMax 凭据的完整端到端流程。
- 不声称存在预构建发行包，因为仓库当前只提供源码运行和本地打包说明。
- 不把唯一已知的 Starlette 依赖弃用警告描述成应用故障。

## 验证方式

- 对比中英文标题层级，确保章节一一对应。
- 检查两份 README 的贡献、安全与 MIT 许可证链接及双语含义一致。
- 检查两份文档中的命令、路径、格式、比特率和静音时长一致。
- 对照 `app/models.py`、`app/config.py`、`app/main.py`、音频服务、测试和构建脚本检查关键事实。
- 搜索应用包路径，确保 README 与构建脚本一致写成 `dist/<arch>/声绘魔法.app`，不将内部名称 `VoiceCanvas` 误写为 `.app` 包名。
- 运行完整自动化测试，确认纯文档改动没有引入仓库异常。
- 检查 `git diff --check` 和最终差异，排除 Markdown 空白错误和无关修改。
