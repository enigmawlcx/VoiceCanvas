# 整篇音频段间增加固定留白设计

日期：2026-07-12

## 背景与目标

工作台在“解析分段”后，会逐段调用 MiniMax 文本转语音接口。用户点击“整篇合成并导出”时，前端收集成功生成的各段音频，再调用后端 `/api/studio/synthesize/concat`；后端通过 pydub/FFmpeg 将音频首尾拼接并导出。项目还保留 `/api/studio/synthesize/full` 后端整篇合成接口，该接口最终复用同一个本地拼接函数。

当前应用没有主动设置段间留白。导出文件中不足 0.2 秒的间隔来自各段 MiniMax 输出自身残留的头尾静音。

本次目标是在每两个成功合成的相邻音频段之间，额外插入固定 500 毫秒静音。不开启音频静音检测，不裁剪模型原有静音，因此最终听感间隔为“模型原有间隔 + 500 毫秒”。导出文件开头和结尾不增加静音，单段试听不受影响。

## 调研结论

MiniMax T2A 支持在同一次请求的可发音文本之间加入 `<#x#>` 停顿标记。但是当前应用为了支持逐段情绪、逐段进度和失败段重试，采用逐段独立请求；停顿标记不能跨请求控制两段音频之间的间隔。改成整篇单次请求会破坏这些既有能力。

MiniMax T2A 按输入字符计费。官方接口响应提供 `usage_characters`，但文档未明确承诺停顿标记字符不参与计费，因此不能将模型停顿方案视为确定的零额外费用方案。

本地拼接已经是现有导出链路的一部分。在本地插入静音不增加 MiniMax 请求、输入字符或费用，并且时长确定，因此采用本地实现。

## 方案选择

### 采用：后端本地拼接时插入静音

扩展 `app/services/synthesize.py` 中的 `concat_audio_bytes()`：解码各段音频后，在相邻音频块之间插入 `AudioSegment.silent(duration=500)`，随后按现有格式导出。

这一位置同时覆盖：

- 工作台实际使用的“逐段合成后调用 `/synthesize/concat`”流程；
- 后端 `/synthesize/full` 整篇合成流程；
- 未来直接复用 `concat_audio_bytes()` 的导出调用方。

### 未采用：前端生成或插入静音

前端实现需要引入浏览器端音频解码、静音片段编码及格式兼容处理，还可能增加传输数据。后端已经承担拼接职责，因此该方案会造成不必要的职责分散。

### 未采用：MiniMax 停顿标记

停顿标记只适用于单次请求内的文本，无法直接作用于当前独立请求返回的音频边界。整篇合并请求会削弱逐段情绪、进度展示和失败重试，并可能产生额外计费字符。

## 数据流与行为规则

1. 前端继续逐段请求 MiniMax 合成，不改变请求内容和参数。
2. 前端只收集成功返回的音频，并按原段落顺序提交给 `/api/studio/synthesize/concat`。
3. 后端逐个解码音频块。
4. 从第二个成功音频块开始，在追加该块之前先追加 500 毫秒静音。
5. 后端按现有设置导出文件并返回文件路径。

具体规则：

- 零个音频块：保持现有错误“没有可拼接的音频”。
- 一个音频块：原样导出，不添加静音。
- N 个成功音频块：添加 N−1 个 500 毫秒静音片段。
- 某段合成失败：失败段不产生占位静音；相邻的两个成功音频块之间只添加一次 500 毫秒静音。
- 文件头尾：不主动增加静音。
- 模型自带静音：不检测、不裁剪。
- 单段试听：不经过整篇拼接，不增加静音。

## 接口与兼容性

不修改 HTTP 接口签名、前端请求结构、配置文件或数据库结构。500 毫秒为本次确定的固定产品规则，不增加界面开关或可配置项。

拼接函数可将 500 毫秒定义为具名常量，避免算法中出现无含义的数字，并为未来明确提出可配置需求时保留单一修改点。该常量不是公开接口。

## 错误处理

保持现有解码、导出和无音频输入错误处理。静音片段由 pydub 在内存中生成，不引入外部 API 或新的失败类型。

生成的静音片段在拼接时应与相邻音频兼容。pydub 在 `AudioSegment` 拼接时负责必要的声道、采样率和采样宽度协调；现有 MiniMax 请求本身也使用统一音频设置。

## 测试与验收

服务测试应覆盖：

- 单段导出时长不额外增加 500 毫秒；
- 两段导出时长约等于两段原始时长之和加 500 毫秒；
- 三段导出包含两处留白，总时长额外增加约 1000 毫秒；
- `synthesize_full()` 中间段失败后，两个成功段之间只增加一处 500 毫秒留白；
- 空列表仍返回既有错误。

由于编码和解码可能产生几毫秒误差，测试按合理毫秒容差断言，不能要求压缩格式输出逐毫秒完全相等。

验收标准：使用工作台解析至少两个段落并执行“整篇合成并导出”，导出音频在每两个成功段之间比当前行为额外增加约 0.5 秒静音；MiniMax 合成请求次数、文本和用量统计均不因本功能增加。

## 范围边界

本次不实现：

- 段间留白时长的界面设置；
- 自动检测、裁剪或补足为“总计恰好 0.5 秒”；
- 段首或段尾留白；
- MiniMax 停顿标记注入；
- 单段试听留白；
- 与本功能无关的音频链路重构。
